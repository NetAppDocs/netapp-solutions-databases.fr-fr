= Déployer SQL Server 2025 sur NetApp AFF à l'aide de LUN iSCSI
:allow-uri-read: 


[role="lead"]
Déployez SQL Server 2025 sur Windows Server 2025 avec des bases de données utilisateur, des journaux de transactions, TempDB et des sauvegardes de journaux sur des LUN iSCSI sur un système NetApp AFF. Cette procédure comprend la configuration d’iSCSI sur la SVM ONTAP, du groupe d’initiateurs et des LUN, de l’initiateur iSCSI Windows, de MPIO et des disques, ainsi que l’installation de SQL Server.



[[scope]]
[[intro-scope]]
== Portée

Cette procédure déploie une instance SQL Server 2025 autonome sur un seul hôte Windows Server 2025, avec les bases de données utilisateur, les journaux de transactions, TempDB et les sauvegardes de journaux sur des LUN iSCSI. La même conception de stockage s'applique aux instances de cluster de basculement SQL Server (FCI) et aux groupes de disponibilité Always On, mais leur configuration spécifique au cluster n'est pas couverte. L'optimisation des performances et le dimensionnement de SQL Server sont également hors du périmètre. Pour connaître les avantages, les composants de la solution, les principes de conception, une explication du fonctionnement du multipathing et la protection des données avec NetApp Console Backup and Recovery, consultez link:sql-iscsi-aff-overview.html["Découvrez SQL Server 2025 sur NetApp AFF avec les LUN iSCSI"].



[[audience]]
[[intro-audience]]
== Public

Cette procédure est destinée à :

* *Administrateurs du stockage*, qui configurent le cluster ONTAP, le SVM, les LIF iSCSI, le groupe d’initiateurs et les LUN.
* *Administrateurs Windows*, qui préparent l'hôte Windows Server 2025, l'initiateur iSCSI, MPIO et les disques.
* *Administrateurs de bases de données*, qui installent et configurent SQL Server 2025 et mettent en place la sauvegarde et la restauration.


Une connaissance de base de l'administration de ONTAP System Manager, de Windows Server et de SQL Server est requise.

TIP: Utilisez un LUN par volume et des volumes séparés pour les données, les journaux, TempDB et les sauvegardes. Cela vous permet d'appliquer des paramètres de QoS, de snapshots, d'efficacité et de réplication différents à chaque volume. Cela permet également d'exclure TempDB, qui évolue constamment, des snapshots de vos bases de données utilisateur.


TIP: Utilisez des LUN supplémentaires sur différents contrôleurs pour les fichiers de données secondaires supplémentaires (.ndf) afin de répartir la charge.



[[prerequisites]]
== Prérequis

Veuillez vous assurer que les conditions suivantes sont remplies avant de commencer :

.NetApp ONTAP
* La paire haute disponibilité AFF est installée, et le cluster est configuré et en bonne santé.
* La licence iSCSI est installée. Elle est incluse dans ONTAP One.
* Il existe au moins un agrégat de données (niveau local) sur chaque nœud.
* La SVM existe déjà. Dans cette procédure, la SVM existante `{svm}` est utilisée ; iSCSI y est ajouté. Pour créer une SVM dédiée au SAN, utilisez menu:Cluster[VM de stockage > Ajouter] et sélectionnez *iSCSI* comme protocole d'accès.
* Les ports du réseau de données, le domaine de diffusion et (en option) les VLAN pour les interfaces iSCSI sont configurés. En laboratoire, le domaine de diffusion `MT9000` utilise des trames jumbo.
* L'heure est synchronisée entre le cluster, l'hôte et Active Directory via NTP.


.Réseau
* L'hôte SQL Server possède au moins une, et de préférence deux, cartes réseau dédiées pour iSCSI dans le sous-réseau ou le VLAN iSCSI.
* L'unité de transmission maximale (MTU) est identique de bout en bout (carte réseau de l'hôte, commutateurs, ports ONTAP). Vérifiez les trames jumbo avec `ping -f -l 8972 <LIF-IP>`depuis l'hôte.


.Windows Server
* Windows Server 2025 (Desktop Experience) est installé, mis à jour et joint au domaine.
* Les NetApp Windows Host Utilities dans une version prise en charge pour Windows Server 2025 sont disponibles (voir le  https://imt.netapp.com/matrix/["Outil de matrice d'interopérabilité (IMT) NetApp"^]).
* Le support d'installation de SQL Server 2025 (ISO) et une clé de produit valide (ou une édition gratuite) sont disponibles.



NOTE: Contrairement aux partages de fichiers SMB, les LUN ne nécessitent pas de compte de domaine pour le service SQL Server. Les comptes virtuels par défaut (`NT Service\MSSQLSERVER`) peuvent être utilisés. Un compte de domaine ou un compte gMSA reste toutefois recommandé si l'instance a besoin d'un accès réseau, par exemple pour sauvegarder sur un partage de fichiers ou pour l'authentification Kerberos.

== Étape 1 : Activer iSCSI sur la VM de stockage

Ajoutez le protocole iSCSI au SVM et créez deux LIF iSCSI sur chaque nœud de la paire haute disponibilité.

.Étapes
. Activez iSCSI sur le SVM et créez les LIF iSCSI avec System Manager ou la CLI :
+
[role="tabbed-block"]
====
.Gestionnaire de système
--
.. Ouvrez un navigateur Web et connectez-vous à ONTAP System Manager à l’adresse  `+https://<cluster-management-IP>+`. Connectez-vous avec le compte administrateur du cluster.
.. Accédez au menu : Cluster[Machines virtuelles de stockage], cliquez sur la SVM `{svm}` et ouvrez l’onglet *Paramètres*. Sous *Protocoles*, la vignette *iSCSI* affiche *Non configuré*. Cliquez sur l’icône en forme d’engrenage de la vignette *iSCSI*.
+
.Afficher un exemple
[%collapsible]
=====
image:sql25_iscsi_bp_004.png["Paramètres de la VM de stockage a50-sql avec iSCSI non configuré,width=800"]

=====

+
*** Nœud `{node1}`: adresse IP `192.168.175.134`, masque de sous-réseau `24`, domaine de diffusion et port `MT9000`
*** Sélectionnez *le même masque de sous-réseau, la même passerelle et le même domaine de diffusion pour toutes les interfaces suivantes*.
*** Deuxième interface sur `{node1}`: `192.168.175.135`
*** Nœud `{node2}`: `192.168.175.136` et `192.168.175.137`
+
Cliquez sur *Enregistrer*.

+

TIP: Une passerelle n'est pas nécessaire lorsque l'hôte et les LIF se trouvent sur le même sous-réseau. Ne routez pas le trafic iSCSI.

.Afficher un exemple
[%collapsible]

.ONTAP CLI

Les commandes suivantes permettent de créer la même configuration depuis l'interface de ligne de commande. Remplacez les valeurs d’espace réservé entre chevrons. Notez le nom de la cible dans la sortie de `vserver iscsi show`; vous en aurez besoin pour vérifier la connexion depuis l'hôte.

cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

NOTE: Les LIF iSCSI ne migrent pas lors d'une prise de contrôle. La haute disponibilité est assurée par les chemins d'accès aux LIF du nœud partenaire ; il est donc impératif de toujours créer des LIF iSCSI sur les deux nœuds de la paire haute disponibilité.

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== Étape 5 : Vérifiez les paramètres du volume et du LUN

Vérifiez les paramètres d'espace et d'instantané des quatre volumes. System Manager utilise des valeurs par défaut appropriées ; les paramètres suivants sont recommandés pour les LUN SQL Server :

[cols="1,1,3"]
|===
| Paramètre | Valeur | Raison 


| Garantie d'espace (volume) | `none` (mince) | La capacité est consommée uniquement lorsque des données sont écrites. 


| réservation d'espace LUN | `disabled` (mince) | LUN fine dans un volume fin. 


| allocation d'espace LUN | `enabled` | Active SCSI UNMAP afin que l'espace libéré dans NTFS soit restitué à ONTAP et permette à l'hôte de réagir correctement lorsque le volume manque d'espace. 


| Politique d'instantané | `none` | Les instantanés qui ne sont pas cohérents au niveau des applications sont inutiles pour SQL Server. Les sauvegardes sont créées par NetApp Console Backup and Recovery. 


| Réserve Snapshot | `0` % | L'espace Snapshot est surveillé à la place avec le dimensionnement automatique du volume. 


| Dimensionnement automatique | `grow`, 130 % maximum de la taille du volume | Empêche la mise hors ligne du LUN lorsque les instantanés consomment de l'espace. 


| efficacité de stockage | activé (par défaut sur AFF) | La déduplication, la compression et le compactage en ligne n'ont aucun impact mesurable sur les performances de SQL Server. 
|===
Utilisez les commandes suivantes pour appliquer et vérifier les paramètres (illustrées pour `sql_iscsi_1_data`) :

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

.PowerShell

Les commandes suivantes mettent les disques NetApp en ligne, les initialisent avec GPT, créent et formatent un volume NTFS avec une taille d'unité d'allocation de 64 Ko sur chacun, et créent les dossiers pour SQL Server.

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

CAUTION: N'exécutez ces commandes que si ces LUN sont les seules LUN RAW connectées au système. Si d'autres LUN RAW sont connectées au système, vous devrez créer manuellement les dossiers et formater les volumes.

== Étape 9 : Vérifiez l’installation

Créez une base de données de test et vérifiez que ses fichiers de données et de journal se trouvent sur les LUN NetApp et que les chemins de stockage sont en bon état.

.Étapes
. Ouvrez le port SQL Server dans le pare-feu Windows :
+
[source, powershell]

PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Installez SQL Server Management Studio (SSMS) à partir du lien *Install SQL Server Management Tools* dans l’Installation Center, ou sur le site web de Microsoft.
. Démarrez SSMS et connectez-vous à l'instance (`{host}`) avec l'authentification Windows. Créez une base de données de test ; ses fichiers de données et journaux sont, par défaut,  `E:\data` et  `F:\log`.
. Vérifiez les emplacements des fichiers avec T-SQL:
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. Vérifiez que l'initialisation instantanée des fichiers est activée :
+
[source, sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----
. Vérifiez le stockage depuis l'hôte et depuis ONTAP :
+
[source, powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source, console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----
. Facultatif : testez la haute disponibilité. Exécutez un workload sur la base de données de test et effectuez une prise de contrôle ONTAP suivie d’une restitution du nœud propriétaire du volume de données (`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`). Le workload s’interrompt pendant quelques secondes, puis reprend ; les bases de données restent en ligne.


.Et ensuite
Protégez les bases de données avec des sauvegardes Snapshot cohérentes au niveau des applications. Pour l’architecture, le workflow de sauvegarde et les avantages, voir link:sql-iscsi-aff-overview.html#console["Protection des données avec NetApp Console Backup and Recovery"].

== Utilisez un script CLI ONTAP pour configurer le stockage en une seule fois

Le script suivant contient la configuration de stockage complète de cette procédure. Remplacez les valeurs entre chevrons avant de l'exécuter.

[source, console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi

== Utilisez un PowerShell script pour configurer l'hôte en une seule étape

Le script suivant contient la configuration hôte complète de cette procédure. Exécutez-le dans une session PowerShell avec privilèges élevés ; la partie MPIO nécessite un redémarrage.

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: Exécutez chaque partie séparément. La partie 1 nécessite un redémarrage de l'hôte ; les autres parties ne pourront donc pas continuer après le redémarrage.


CAUTION: N’exécutez les commandes de la partie 3 que si ces LUN sont les seules LUN RAW connectées au système. Si d’autres LUN RAW sont connectées au système, vous devrez créer manuellement les dossiers et formater les volumes.
